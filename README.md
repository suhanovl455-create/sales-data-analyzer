# Sales Data Analyzer

Приложение на Python для анализа выгрузки заказов: проверка CSV, показатели продаж, графики и экспорт результатов. Работает локально через Streamlit. В комплекте демонстрационные синтетические данные.

## Возможности

- Загрузка CSV в UTF-8; разделитель — запятая, точка с запятой или табуляция.
- Проверка обязательных значений, дат, статусов, количества и цены.
- Поиск точных повторов, конфликтов товарных строк и реквизитов заказа.
- Фильтр периода, выручка, средний чек, оплаченные заказы и повторные покупатели.
- Графики дневной выручки, продажи категорий, топ-10 товаров.
- Экспорт ZIP: принятые строки, ошибки, выбранный период, агрегаты и JSON с показателями.

## Запуск

Python 3.12 (проверено на macOS):

```sh
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements-lock.txt
streamlit run app.py
```

Открыть адрес, показанный в терминале. Приложение привязано к 127.0.0.1. По умолчанию выбран пример; для своего файла переключите источник в боковой панели.

Без интерфейса:

```sh
python cli.py data/demo_sales.csv
```

Архив появится в `output/sales_analysis.zip`.

## Формат CSV

| Столбец | Содержание |
|---|---|
| order_id | Идентификатор заказа |
| customer_id | Идентификатор клиента |
| order_date | Дата YYYY-MM-DD |
| status | paid / cancelled |
| product_id | Идентификатор товара |
| category | Категория |
| quantity | Положительное целое количество |
| unit_price_rub | Цена единицы в рублях, до двух знаков после запятой |

Одна строка — товар в заказе. Пара `order_id + product_id` уникальна. Несколько строк одного заказа должны иметь одинаковые дату, клиента и статус. Денежные значения преобразуются в целые копейки через Decimal; округление не исправляет ошибочную цену автоматически.

Точный повтор удаляется после первого вхождения. Все корректно разобранные строки заказа с конфликтующими реквизитами или товарными ключами исключаются. Строка с неверными полями исключается отдельно: при этом заказ может остаться частичным. Перед использованием показателей такие ошибки следует исправить в источнике. В отчёте сохраняются порядковые номера записей исходного CSV (заголовок считается первой записью).

## Определения показателей

Выручка — количество × цена для paid. Средний чек — выручка / число уникальных оплаченных заказов. Повторный покупатель имеет минимум два оплаченных заказа в выбранном периоде. Знаменатель — покупатели хотя бы с одной оплатой. В дневном графике дни без продаж между границами периода заполнены нулями.

Проверка качества относится ко всему файлу; фильтр дат влияет на показатели и таблицу выбранного периода. Отменённые строки сохраняются среди принятых данных, но не входят в показатели продаж.

## Проверка

```sh
python -m unittest discover -s tests -v
```

Тесты проверяют расчёт заказов с несколькими товарами, деньги, повторы, конфликты, даты, нулевые и ошибочные цены, отсутствие продаж, границы периода и содержимое ZIP. В демонстрационный CSV включены ошибки для проверки интерфейса.

## Проверенный пример

В демонстрационном файле 376 строк: принято 366, исключено 10. Выручка — 1 378 900 ₽, оплаченных заказов — 161, средний чек — 8 564,60 ₽. Среди 57 покупателей с оплатой 43 совершили повторные покупки в периоде.

Файл `requirements-lock.txt` фиксирует проверенные версии зависимостей. `requirements.txt` задаёт допустимые диапазоны для дальнейшего обновления.

## Структура

```text
analyzer.py       # проверка, расчёты, экспорт
app.py            # интерфейс Streamlit
cli.py            # запуск без интерфейса
data/             # пример CSV
tests/            # проверки расчётов
```

## Ограничения

Весь файл обрабатывается в памяти; интерфейс ограничен загрузками до 10 МБ. Поддерживается заданная схема, сопоставления произвольных колонок нет. Не учитываются возвраты, доставка, скидки, налоги и себестоимость. Выручка не является прибылью. Это учебный проект, демонстрационный набор не описывает реальный магазин.
